# Roadmap — hyperframes-skill

Part of the [AI Video Production OS](https://github.com/kajisho5/AI-video-production-OS/blob/main/docs/ecosystem/ROADMAP.md) ecosystem: department **映像 (Visual)**, status `active`.
Written from a read-only audit of this repository on 2026-10-30. Each step below is meant to be one pull request; tick it off by linking the PR.

## Where it stands

v0.8.0, released by its workflow (step 2). Node 22. batch, doctor, preview, probe, render (h264, VP9 with alpha, ProRes 4444, PNG sequence; straight alpha), scene, template (break, lower-third, session-slate, title-card). IN / LOOP / OUT segments with a measured loop seam (step 12) and alpha deliveries (step 13). CI on Ubuntu + macOS, and Windows since [#14](https://github.com/kajisho5/hyperframes-skill/pull/14). Stinger templates (geometric, glitch, particles, brush, logo reveal) with a measured cover and `stinger.json`, and `title.json` beside title material (steps 15, 17). No brand input yet (step 16).

## Wiring

The agent names `hyperframes-skill/render` in a CONFIRM handoff from a pinned contract (step 5, video-production-agent#95); it does not run it yet. Under the [Velisa ownership decisions 2026-11-12](https://github.com/kajisho5/Velisa/pull/156) (O1), the animated-overlay path is: this skill renders the material (segments, alpha), and motion-graphics-skill's `rendered_layer` places it; the missing piece is an agent path that runs `render` and passes its output to `motion.layer` (step 18). Calls ffmpeg/ffprobe directly, bypassing ffmpeg-skill (the engine bypass, [docs/design-decisions.md D3](docs/design-decisions.md)); `render` reads its output back through ffmpeg-skill/probe when a checkout is present and reports `ffmpeg_skill.status`.

- [ ] **7. Text animation (kinetic typography)** — text layers animate per character, word or line: staggered reveal (`transition_in.type: chars|words|lines` with `stagger` and `easing`), mask wipes, tracking (letter-spacing) and scale animation, and variable-font axis keyframes (`font_variation`). Units are grapheme clusters (Unicode UAX #29), so combining marks, emoji and Indic / Thai clusters animate whole. CSS animations only, seeked frame by frame as the three transitions are today, so renders stay `bit_exact` on one machine. Field review 2026-11-05 (Velisa ROADMAP, third round)
  - Why: kinetic type for text-only promos, openings and speaker intros comes from a JSON request alone（なぜ要るか：文字だけのPV・オープニングの文字の動きを指定だけで作れる）
  - Done when: a fixture with a per-character reveal renders the expected grapheme count per frame (framemd5 stable across two runs); an unknown axis is refused with the font's real axes listed
- [ ] **8. International typesetting and text fit** — language-aware layout from the layer's `lang`: right-to-left and bidirectional text (Arabic, Hebrew), CJK line breaking, line-break rules per language (Unicode UAX #14; phrase breaks with BudouX, Apache-2.0, run locally, where it supports the language), and `fit: shrink`, which reduces the font size inside the box down to a stated minimum and reports the size used. Text is never cut or ellipsised; a line that does not fit at the minimum is an error with the overflow in pixels. Regional profiles, opt-in and never the default: vertical writing (`writing_mode: vertical`) and ruby annotations for Japanese and Chinese, strict kinsoku
  - Why: long names, affiliations and talk titles in any language shrink and break cleanly, so a lower third never overflows（なぜ要るか：長い氏名・所属・演題を多言語で自動縮小・改行できる）
  - Done when: fixtures in English, Arabic (RTL), Hindi and Japanese render inside their boxes with the reported sizes; the vertical-writing and ruby profiles render as expected; the reported size equals the one in the HTML
  - Re-scoped by the [Velisa ownership decisions 2026-11-12](https://github.com/kajisho5/Velisa/pull/156) (O4): this is now the typesetting of the title material this skill owns (the former motion-titles scope), so it covers every template that carries text (lower-third, title-card, session-slate, break, and the stingers of step 15), not only free scenes. The size used, the breaks and the font per text layer are written into `title.json` (step 17); burned-in titles keep their own fit in motion-graphics-skill
- [ ] **9. Shape and pattern layers** — `shape` layers (rect, rounded rect, circle, line, polygon; stroke, gradient, rotation) with keyframed position / scale / rotation / opacity, and `pattern` presets drawn in SVG / CSS from a seed: grid, lines, dots, concentric rings, morphing polygons. Parameters are typed (count, speed, palette), never raw CSS
  - Why: geometric looks and logo backgrounds without any footage, reproducible from a seed（なぜ要るか：幾何学模様の映像を素材なしで再現性よく作れる）
  - Done when: each preset renders twice to the same framemd5; a changed seed changes the picture and nothing else
- [ ] **10. Generative layer (Three.js / GLSL)** — `type: generative` runs one of the programs this skill ships (particles, noise field, shader gradient, 3D type from a font file) with a seed and typed parameters, through a HyperFrames custom frame adapter that sets the program's time from the frame number. three (MIT) is bundled, never fetched from a CDN; rendering stays on SwiftShader as today, so the output is deterministic on one machine. A user's own fragment shader is accepted only as a local file, checked to contain no network or DOM access. Reference: @hyperframes/core frame adapters (Apache-2.0), three.js (MIT)
  - Why: particles, shaders and 3D type in the same scene, with no separate tool（なぜ要るか：パーティクルやシェーダー、3Dタイポを同じシーンに重ねられる）
  - Done when: a particles fixture renders bit-identical twice; frame N rendered alone equals frame N of the full render; doctor reports the WebGL backend
- [ ] **11. Audio and beat lock** — an `audio` layer (local file; HyperFrames has audio support upstream) so the output carries sound, and `bpm` or a beat grid file (ffmpeg-skill `scenes --beats`, or sound-design-skill's tempo map) to which layer starts and staggers snap. The snapped times are written in the result
  - Why: "neon, 120 BPM, 15 s, vertical" lands every move on the beat, with the music in the file（なぜ要るか：BPM に動きを合わせ、音入りで書き出せる）
  - Done when: at 120 BPM every snapped start is a multiple of 0.5 s within one frame; the output's audio duration equals the scene's
- [x] **12. IN / LOOP / OUT segments and seamless loops** ([#20](https://github.com/kajisho5/hyperframes-skill/pull/20), D12; the loop seam is measured by `render --segments` itself, since qc-skill's loop seam check covers audio only) — a scene declares `segments` (in, loop, out); `render --segments` writes one file per segment plus the full preview, and the loop segment is built so its last frame leads into its first (every animation in it has a period that divides the loop length; a layer that does not is refused). Frame counts per segment are in the result
  - Note: ffmpeg-skill's seamless-loop work (Velisa ROADMAP proposal 10, accepted, top priority: [ffmpeg-skill#422](https://github.com/kajisho5/ffmpeg-skill/issues/422)) smooths a loop after the fact; this step makes the loop seamless by construction
  - Why: in an edit a lower third holds for any length (IN, the loop repeated, OUT), and a loop runs without a visible seam（なぜ要るか：編集でテロップを好きな長さで出し、ループ素材を継ぎ目なく使える）
  - Done when: a lower third with in 0.5 s / loop 4 s / out 0.5 s gives three files whose frame counts add up to the full render; qc-skill's loop seam check passes on the loop
- [x] **13. Alpha deliveries** ([#21](https://github.com/kajisho5/hyperframes-skill/pull/21), D13) — besides ProRes 4444: WebM VP9 with alpha, PNG sequence, and a stated `alpha: straight|premultiplied` recorded in the result; transparent background checked on an output frame
  - Why: web players take WebM with alpha, After Effects and NLEs take PNG sequences or ProRes 4444（なぜ要るか：編集先ごとに求められるアルファ形式で出せる）
  - Done when: each format's first frame has alpha 0 in an empty corner and 255 on a solid layer, read back by probe
- [ ] **14. Style presets and recipe gallery** — preset templates built on the steps above: swiss, minimal, neon, glitch, corporate logo reveal, and regional styles as options (for example wafu, Japanese), each a template with typed values (copy, colours, font, bpm, aspect) and a brand kit as input; `template --gallery` renders one still per preset for choosing. Each preset has a fixed check scene rendered in CI. Reference, ideas only, no code used: video-shotcraft recipe cards (Apache-2.0), motion-video-kit's Gauntlet (MIT), the official Remotion and HyperFrames templates (each template's licence checked in an ADR)
  - Why: start from "make it neon" and compare stills before rendering（なぜ要るか：一言のスタイル指定から始め、静止画で比べて選べる）
  - Done when: six presets, each with a CI check scene; a preset given a brand kit uses only the kit's colours and font
- [x] **15. Stinger templates with a cut point** ([#23](https://github.com/kajisho5/hyperframes-skill/pull/23), D14; no audio yet: `audio: false` until step 11) — stinger scenes (geometric, particles, brush, glitch, logo reveal) of a stated length whose graphic covers the whole frame from a stated cut point (`--duration 1.2 --cut-point 0.5`), with optional audio; the result writes `stinger.json` beside the file (cut point in frames and seconds, the fully covered window, alpha mode) for video-editing-skill's stinger transition to cut at
  - Why: a stinger is a transition inside an edit: the cut happens while the graphic covers the picture, so its cut point must be exact data, not a guess（なぜ要るか：スティンガーのカット点をデータで渡し、編集で正確に切り替えられる）
  - Done when: a 1.2 s stinger with a cut point at 0.5 s has full cover at frame 15 (30 fps), checked by qc-skill's stinger cut-point check, and `stinger.json` gives the same frame
  - Re-scoped by the [Velisa ownership decisions 2026-11-12](https://github.com/kajisho5/Velisa/pull/156) (O4): the stinger part of the former motion-titles scope lands here. `stinger.json` follows the Velisa spec for title and stinger metadata (in progress in Velisa), which documents the shape the receivers already read: video-editing-skill's CONCAT `transition: {type: stinger, stinger, cut_point, cover}` and qc-skill's `VideoRule.stinger {cut_point, cover}`. No field is invented here; a field the spec lacks is proposed to Velisa first. The templates take the brand kit of step 16, and key / fill or premultiplied copies come from ffmpeg-skill `export` (`key-fill`, `--alpha-mode`), not from a second encoder here
- [ ] **16. Brand input (`kit@1`)** — every template and scene takes a brand kit in the Velisa `kit@1` shape (a superset of ffmpeg-skill's `brand.json`: colours, font and font file, logo, safe margin), mapped onto the template's typed values; the values used are written in the result. An explicit template value wins over the kit; a kit colour or font that a template cannot use is reported, not dropped silently. [Velisa ownership decisions 2026-11-12](https://github.com/kajisho5/Velisa/pull/156) (O4, O5)
  - Why: lower thirds, title cards and stingers come out in the event's or channel's colours and font without listing them per template（なぜ要るか：ブランドの色・書体・ロゴを毎回並べずにテロップ素材へ反映できる）
  - Done when: one `kit@1` file renders lower-third, title-card and a stinger whose sampled colours and font match the kit (pixels / the font reported by the result); the same file read as ffmpeg-skill `brand.json` gives the same colours
- [x] **17. `title.json` beside title material** ([#23](https://github.com/kajisho5/hyperframes-skill/pull/23), D14; the font size is the one given until step 8 fits text) — `render` of a title template (lower-third, title-card, session-slate, break) writes `title.json` beside the file, in the Velisa spec for title metadata (in progress in Velisa): segments with frame counts (as the result already has), alpha mode, the loop seam measurement, the safe area used, the text drawn and the font size used (step 8). Like `stinger.json`, it records the shape the receivers already read (motion-graphics-skill `rendered_layer` `in_duration` / `out_duration` / `loop`, qc-skill, the agent) and adds nothing they do not read. [Velisa ownership decisions 2026-11-12](https://github.com/kajisho5/Velisa/pull/156) (O4)
  - Why: whoever places or checks the material reads its timing and alpha from a file, not from a guess or a second probe（なぜ要るか：配置・検査する側が IN/LOOP/OUT とアルファをファイルから読める）
  - Done when: a lower third rendered with `--segments` writes a `title.json` that validates against the Velisa spec, and motion-graphics-skill places the same file from it with the in, loop and out at the right frames
- [x] **18. (agent side) Run `render` and pass the output to `rendered_layer`** — the agent's `html_scene_render` goes from a CONFIRM handoff to a run, and its ProRes 4444 output (`rendered_layer` refuses VP9 alpha WebM) with `title.json` goes to `motion.layer`. This is the one animated-overlay path under the [Velisa ownership decisions 2026-11-12](https://github.com/kajisho5/Velisa/pull/156) (O1); ffmpeg-skill overlay keyframes are not needed for it
  - Done when: tracked in video-production-agent
  - Done (video-production-agent [#155](https://github.com/kajisho5/video-production-agent/pull/155), ADR-114, its step 29): `--set motion.layer=hyperframes` (opt-in) plans `html_scene_layer`, which runs `template` → `scene` → `render --codec prores` (`--segments` with `hyperframes.segments`) and admits the clip only as a verified ProRes `.mov` with straight alpha and the planned segments; `rendered_layer` then places it with in / out / loop from those segments, with no file supplied by the user. Without hyperframes-skill (or Node / a headless Chromium) the step is handed off as before. hyperframes-skill pinned at 0.8.1 there. The agent takes in / out / loop from the rendered segments; `rendered_layer` reading `title.json` itself is motion-graphics-skill step 12

## Boundaries

Titles burned into a programme are motion-graphics-skill's (`タイトル・テロップ`); title and stinger material files are this skill's (`テロップ・スティンガー・ループ素材`); remotion-ffmpeg-skill's titles stay inside its own compositions ([Velisa ownership decisions 2026-11-12](https://github.com/kajisho5/Velisa/pull/156), O9). Kinetic typography and geometric motion are this skill's; audio visualizers and the beat- or lyric-measured versions are remotion-ffmpeg-skill's; blender-skill stays 3D only (O17). Placement on a programme is motion-graphics-skill's `rendered_layer`, a stinger between two clips is cut by video-editing-skill, and the checks on the material (cut-point cover, loop seam, alpha edge, key / fill) are qc-skill's.
